# 행복한아이 센터 통합 업데이트 — 2026-11-09

이 폴더는 11월 6일 수정본과 월별 수업 기능을 모두 포함한 통합본입니다. 이전 압축파일을 먼저 적용할 필요가 없습니다. 기존 프로젝트를 복사해 만든 수정본입니다. D: 원본과 운영 Supabase에는 이번 작업의 변경을 적용하지 않았습니다.
현재 단계는 테스트 환경 적용용입니다. 아래 운영 데이터 확인과 권한 점검을 마친 뒤 운영에 반영하세요.

## 반영한 기능

- 관리자 메인/정기수업 관리의 등록·수정·종료를 같은 서버 처리로 통합했습니다.
- 변경 적용일 이전 일정과 출결을 유지합니다. 적용일 이후의 기존 미진행 일정을 취소하고 새 요일의 일정을 생성합니다.
- 규칙은 이전 버전을 남기고 새 버전으로 연결합니다. 종료일을 줄여도 기존 종료일 뒤의 미래 일정이 남지 않도록 적용일 이후 전체 범위를 처리합니다.
- 변경 구간에 이미 출결이 있는 수업은 자동 삭제하지 않고 변경을 중단합니다. 적용일을 조정하거나 해당 기록을 먼저 검토해야 합니다.
- 중간 오류가 나면 정기 규칙·일정 변경 전체가 취소됩니다. 일정 취소는 실제 삭제 대신 비활성 처리하고 취소 사유를 남깁니다.
- 개별 취소한 정기 회차는 예외로 기록해 같은 날짜를 재생성하지 않습니다.
- 일반 일정·그룹 일정 저장도 한 번에 처리합니다. 학생/담당자 시간 충돌을 검사합니다.
- 그룹 변경 범위를 선택한 회차로 제한합니다. 정기수업 변경은 정기수업 화면에서만 처리합니다.
- 출결과 즉시 보강 예약을 한 번에 저장합니다. 보강 예약이 실패하면 출결만 남지 않습니다.
- 보강 1회는 40분입니다. 정규수업 길이를 변경하지 않았습니다. 기존 화면처럼 시간보강 입력은 10분 단위입니다.
- 보강 선택에서 결석 날짜·담당자·시간을 구분하고 결석 기록 ID에 연결합니다. 같은 날 여러 결석을 날짜만으로 추정하여 차감하지 않습니다.
- 예약은 완료로 차감하지 않습니다. 완료 횟수/분, 예약 분, 남은 분을 구분합니다. 완료+예약 합계가 40분을 넘는 새 예약을 차단합니다.
- 선생님 CSV에 일반/일보강/시간보강, 원래 결석일, 출결 상태, 예정/완료 보강 분, 잔여 내역을 추가했습니다.
- 학생 CSV는 일정 수와 실제 완료 수를 구분하고 시간보강 사용 횟수/분과 잔여 내역을 출력합니다. 그룹의 두 담당자가 같은 학생 수업을 중복 집계하지 않도록 정리했습니다.
- 주차별 CSV와 관리자 집계는 활성 일정 대조/최신 출결 선택을 공유합니다. CSV와 주요 관리자 조회는 페이지를 나누어 읽어 기본 행 수 제한으로 잘리는 문제를 줄였습니다.
- /admin/schedule은 현재 관리자 시간표로 연결됩니다. 이전 weekly_schedules 저장 API는 410 응답으로 중단했습니다. 기존 테이블의 데이터는 삭제하거나 자동 병합하지 않습니다.
- API/화면 HTML을 캐시에서 잘못 반환하지 않도록 서비스 워커를 수정했습니다.

## 월별 수업 관리 사용법

관리자 화면 → **월별 수업·이월**에서 이용합니다.

- 같은 아이 + 같은 선생님 + 같은 바우처의 모든 요일을 합쳐 월 4회입니다. 일반 일정으로 등록한 정규 회차도 포함하며 보강은 제외합니다.
- 정규 배정 횟수와 실제 출석/결석/미처리 횟수는 구분합니다. 결석은 원래 배정된 정규 회차에 포함하고, 그 결석의 보강은 별도로 관리합니다.
- 3회로 끝내는 달: **3회 예외 설정** → 사유 입력 → 출결 처리 후 **월 마감**. 목표를 줄였다고 남은 일정을 자동 삭제하지 않습니다.
- 11월 3회 + 12월 5회 예시: 12월 화면에서 해당 정규 회차의 **전월분 배정**을 누르면 11월 4회, 12월 4회로 집계됩니다. 실제 수업 날짜와 출결 날짜는 12월 그대로 보존됩니다.
- 전월분 배정은 같은 아이/선생님/바우처의 바로 전월에 부족분이 있을 때만 가능합니다. 두 달 이상 건너뛰거나 다른 선생님/바우처로 부족분을 옮기지는 않습니다.
- 당월 일정이 5회이고 전월 부족분도 없으면 **휴무 취소**로 해당 회차를 취소할 수 있습니다. 자동으로 5번째 수업을 삭제하지 않습니다. 출결이 있으면 취소할 수 없습니다.
- 이월 배정된 일정을 수정/취소하려면 먼저 **배정 해제**를 합니다. 마감된 월은 **마감 해제**가 먼저입니다.
- 월 마감은 배정 횟수가 목표와 일치하고 미래 일정/미처리 출결이 없어야 가능합니다. 마감한 정규수업 출결은 다른 경로에서도 수정이 차단됩니다. 보강 진행은 계속 가능합니다.
- 선생님/바우처를 변경하면 새 조합의 월별 항목으로 표시합니다. 과거 기록과 보강은 보존하며, 서로 다른 조합의 월 목표/이월을 자동 합치지 않습니다.
- 월별 화면의 CSV는 횟수 반영 월 기준입니다. 기존 학생/선생님 CSV는 실제 수업 월 기준이며 선생님 CSV에 **정규횟수반영월**을 추가했습니다. 청구 산식은 변경하지 않았습니다.
- 월별 보강 요약에서 수업을 확실하게 연결할 수 없는 과거 보강은 별도 경고합니다. 전체 보강 잔여량은 관리자 보강 상세에서 확인합니다.

## 이번 수정본에 포함되지 않은 내용

1. 서로 다른 선생님·바우처 사이의 자동 월 목표 통합 및 두 달 이상 건너뛰는 이월.
2. 과거 데이터 자동 정정. 이미 물리적으로 삭제된 기록은 복구하지 않았습니다. 연결 태그가 없는 정기 일정이나 날짜만 기록된 모호한 보강은 자동으로 합치거나 지우지 않습니다.
3. 기존 정산 정책 재설계. 학생 CSV의 금액은 기존 일정 기반 산식을 유지하고 제목을 '일정기준금액'으로 명시했습니다. 청구 확정용으로 사용하기 전 휴무/취소/시간보강 금액 정책을 별도 확인해야 합니다.
4. 전체 인증/RLS 전환. 새 수정/취소/출결 API는 서명 세션과 실제 계정 권한을 확인하고 새 RPC는 service_role만 실행할 수 있습니다. 그러나 기존 public 테이블의 넓은 anon 권한과 기존 다른 API의 인증 문제는 남아 있습니다. 기존 클라이언트가 DB에 직접 접근하는 부분이 있으므로 RLS만 일괄 활성화하지 마세요. 운영 공개 전 별도 권한 정비가 필요합니다.
5. 실제 운영 DB 접속 및 브라우저 사용자 시나리오 검증. 본 검증은 전달된 스키마와 합성 데이터로 진행했습니다.

## 파일 적용 순서

### 1. 현재 데이터 확인

운영 DB 백업을 확보하고, Supabase SQL Editor에서 `migrations/000_preflight_readonly.sql`만 먼저 실행하세요. 이 파일은 조회 전용입니다.
- weekly_schedules에 남아 있는 기록은 현재 schedule_entries와 별도로 검토해야 합니다. 이번 수정본은 이를 자동 이관하지 않습니다.
- 태그 없는 일정 수에는 정상적인 일회성 수업도 포함됩니다. 숫자가 0이 아니라고 삭제하면 안 됩니다.
- 중복 출결/같은 날 여러 수업 결석은 날짜별 자동 연결을 피해야 하는 확인 대상입니다.
- 과거 삭제/비활성 일정에 남은 출결과 모호한 연결은 실제 사례별로 대조하세요.

### 2. 테스트 Supabase에 SQL 적용

운영과 분리된 테스트 DB에서 현재 구조를 준비한 뒤 **migrations/APPLY_ALL.sql 하나를 실행하면 001~007 전체가 한 트랜잭션으로 적용됩니다.** 아직 앞선 수정본을 적용하지 않은 경우 이 방법을 권장합니다. 하나라도 실패하면 통합 변경 전체가 롤백됩니다.

개별 검토/적용이 필요하면 아래 순서로 적용할 수 있습니다. 통합 파일을 실행했다면 개별 파일을 다시 실행할 필요는 없습니다.
1. `001_regular_changes.sql` — 규칙 버전/회차 연결/적용일 변경
2. `002_cancel_occurrences.sql` — 회차 취소 및 재생성 예외
3. `003_retire_legacy_delete.sql` — 이전 직접 삭제 RPC의 브라우저 실행 권한 회수
4. `004_attendance_links.sql` — 출결↔일정, 보강↔결석 연결
5. `005_atomic_schedule_save.sql` — 일반/그룹/보강 일정 저장
6. `006_atomic_attendance.sql` — 출결 및 보강 동시 저장
7. `007_monthly_lessons.sql` — 월 목표, 3회 예외, 전월분 배정, 마감 및 수정 보호

하나라도 실패하면 다음 파일로 넘어가지 말고 오류를 확인하세요. 기존 초기화 SQL(DROP TABLE 포함)은 실행하지 마세요.
SQL과 앱 수정본은 함께 사용하는 버전입니다. SQL 없이 새 앱을 실행하면 해당 함수/컬럼이 없다는 오류가 발생합니다.

### 3. 앱 설정과 확인

프로젝트 폴더에서 다음을 실행합니다.

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
npm.cmd run dev
```

기존 환경 설정의 다음 항목을 테스트 프로젝트 값으로 설정하세요. 파일에 실제 키는 포함하지 않았습니다.
- NEXT_PUBLIC_SUPABASE_URL
- NEXT_PUBLIC_SUPABASE_ANON_KEY
- SUPABASE_SERVICE_ROLE_KEY (서버 전용)
- APP_SESSION_SECRET (기존 로그인 서명과 일치)

### 4. 실제 화면 검증

- 월요일 정기 등록 → 지정일부터 화요일 변경 → 이전 월요일 기록과 이후 화요일 일정 확인
- 기간 단축/종료 → 지정일 이후만 취소되는지 확인
- 한 회차 취소 → 같은 날짜가 재생성되지 않는지 확인
- 이미 출결된 일정 수정/취소 시 기록을 보존하고 중단하는지 확인
- 개인/그룹 일정 변경 실패 시 일부만 저장되지 않는지 확인
- 일반 결석 1회 → 시간보강 10분+20분 완료 → 사용 2번/30분/남음 10분 확인
- 일보강 예약 상태 → 잔여 40분 유지, 완료 시 0분 확인
- 같은 날짜 두 수업 결석 → 각각 다른 결석 수업 선택 및 연결 확인
- 원래 결석이 5월이고 보강이 10월인 사례 → 선생님 CSV의 일보강/결석일/출결 상태 확인
- CSV는 선택한 월 말 기준입니다. 현재 누적 화면과 비교할 때 조회 시점을 맞추세요.
- 설치형 앱은 새 버전에서 완전히 닫았다가 다시 열어 캐시 업데이트를 확인하세요.

### 5. 운영 반영

실제 데이터 확인, 위 검증, 권한 정비 후에 운영 반영을 진행하세요. 운영 작업은 이 수정본 작성 과정에서 실행하지 않았습니다.
운영 앱과 SQL 적용 시점을 맞추고, 테스트에서 확인한 순서로 반영해야 합니다.
업데이트 이후 신규 데이터가 생긴 상태에서 예전 앱만 되돌리는 방식은 권장하지 않습니다. 새 규칙 버전과 연결 정보를 이해하지 못하는 예전 저장 경로가 다시 사용될 수 있습니다.

## 추가 수정 — 테스트 검토 반영

- 비활성 정기등록만 남은 빈 월별 항목은 자동 목표에서 제외하고 실제 과거 일정과 보강 이력은 유지합니다.
- 월별 화면에 전체 요약, 부족·초과/보강/출결 대기/마감 필터, 12개씩 목록 보기, 접을 수 있는 회차 상세를 추가했습니다.
- 선생님 CSV는 관리자 인증을 확인하는 서버에서 전체 기간 이력을 페이지별로 읽습니다. 브라우저의 직접 DB 조회 권한에 의존하지 않습니다.
