# 검토 요약

## 핵심 원인

1. 정기수업을 수정하는 두 화면이 서로 다른 삭제/재생성 코드를 사용했습니다.
2. 일부 수정이 기존 일정을 적용일과 관계없이 삭제하거나 새 종료일 안쪽만 처리해 잔여 일정을 남겼습니다.
3. 그룹 ID만으로 수정하면 여러 날짜/담당자의 회차까지 영향을 줄 수 있었습니다.
4. 일정 편집이 날짜/학생/담당자 조건으로 출결을 물리 삭제하는 경로가 있었습니다.
5. 예약 정보와 완료 정보를 혼용하고, 결석 날짜만으로 보강을 묶었습니다.
6. CSV는 화면 계산을 공유하지 않았고 보강 유형/결석일을 출력하지 않았습니다.
7. 일부 조회에 기본 행 수 제한이 적용될 수 있었습니다.
8. 옛 weekly_schedules 화면과 현재 schedule_entries 화면이 공존했습니다.

## 수정 후 기준

- 정기수업 변경은 적용일 경계, 버전 보존, 원자적 처리입니다.
- 선택한 회차만 취소하고 이력을 보존합니다.
- 출결 입력된 미래 회차와 충돌하면 변경을 중단합니다.
- 새 보강은 결석 기록 ID에 연결하고 40분 단위로 예약/완료를 구분합니다.
- 같은 계산 모듈을 관리자 보강 상세/CSV에서 사용합니다.
- 기존 데이터의 모호한 연결은 검토 대상으로 남깁니다.

## 이번 통합본에 추가한 기능

- 요일에 관계없이 같은 아이·선생님·바우처의 정규수업을 월 4회로 합산합니다. 보강은 제외합니다.
- 사유를 남기는 3회 예외, 다음 달 회차의 전월분 배정, 5주차 휴무 취소, 월 마감·해제를 제공합니다.
- 마감과 이월 배정을 DB에서 보호해 다른 일정 수정 경로가 월별 기록을 바꾸지 못하게 했습니다.
- 월별 화면 CSV와 기존 선생님 CSV에 반영 기준을 구분했습니다.

## 운영 전 남은 확인

- 기존 DB의 연결 누락/중복/legacy weekly_schedules 기록 대조.
- public 테이블 anon 권한과 기존 API 인증 범위 정비.
- 실제 브라우저/운영과 동일한 테스트 프로젝트에서 사용자 시나리오 확인.
- 월별 목표는 같은 아이·선생님·바우처 기준으로 구현했습니다. 담당자/바우처 변경 전후 항목을 합치는 정책은 별도 확인 대상입니다.
- 일정 기반 금액과 청구 정책 검토.

새 앱을 운영에 적용했다거나 모든 기존 오류를 해결했다고 판단할 단계는 아닙니다. 수정 소스와 SQL을 테스트할 수 있도록 준비한 후보 버전입니다.
